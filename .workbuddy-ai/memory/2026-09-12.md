## Gejala
User melaporkan kolom JP di AI CV (ai_form) sebagian tidak ikut terisi saat
minta AI menerjemahkan.

## Akar masalah (3 bug, semua terverifikasi)

1. **State tidak tersinkron (regresi refactor a64ef65)** — `js/pages/ai-chat.ts`
   memakai `deps.latestCandidateData = merge(...)`. `deps` cuma objek sementara
   dari `getChatDeps()`, jadi variabel modul `latestCandidateData` di
   `js/pages/ai_form.ts` TIDAK ikut berubah → `updateFormUI()` & `saveToLocal()`
   membaca state lama → form tidak pernah terisi dari balasan AI (termasuk _jp).
   Sebelum refactor: `latestCandidateData = mergeCandidateData(...)` (benar).
   Fix: tambah `setLatestCandidateData` ke `ChatDeps` + dipanggil sebelum
   `updateFormUI()`.

2. **`setNested` tidak array-aware** (`netlify/functions/_lib/ai/chat.ts`) —
   selalu membuat `{}` untuk segmen numerik, jadi hasil translate
   pendidikan/pekerjaan/keluarga jadi `{"0": {...}}` (objek, bukan array) →
   frontend membacanya sebagai objek → baris riwayat kosong.
   Fix: buat `[]` bila segmen berikutnya numerik.

3. **Guard array `_id` asimetris** (`chat.ts`) — `else if (inAi && inAi !== origId)`
   tidak memulihkan `_id` bila model mengembalikannya sebagai string kosong
   (terbukti: `sekolah_id` jadi "", `perusahaan_id` hilang dari balasan).
   Fix: hapus syarat `inAi &&` supaya kontraknya sama dengan field non-array.

# Lanjutan — bersihkan 3 masalah pra-eksisting (gate test jadi 100% hijau)

## 1. `tests/ping.test.ts` usang → diperbaiki
Tes masih memakai kontrak Netlify Functions **v1** (`import { handler }`,
`result.statusCode`, `result.body`, `result.headers`), padahal `ping.js` sudah
**v2** (`export default (req, context) => Response`). Ketiga tes selalu gagal.
Fix: `import handler from ...ping.js` + `new Request(url)` → `res.status`,
`await res.json()`, `res.headers.get(...)`. Tes "uptime increases between calls"
diganti jadi "uptime = detik non-negatif & tidak menurun" — uptime dihitung
`Math.floor(ms/1000)` jadi jeda 10 ms memang tidak bisa menaikkannya.

## 2. `netlify/functions/_lib/session.test.ts` FLAKY → diperbaiki
`it('wrong secret produces different signature')` menandatangani dua token lalu
`expect(verifyToken(t1)).toEqual(verifyToken(t2))`. `signToken` menyematkan
`iat`/`exp` dari `Date.now()` → beda milidetik = payload beda = gagal ~1/3 run.
Fix: `vi.useFakeTimers()` + `vi.setSystemTime(...)` (try/finally `useRealTimers`),
nama tes diganti sesuai maksud sebenarnya + assertion deterministik
(`token1 === token2`). Diverifikasi 5/5 run hijau.

## 3. `scripts/build-netlify-functions.sh` gagal total di Windows → diperbaiki
`$ROOT` (path gaya MSYS `/e/...`) diteruskan ke `esbuild.exe` native Windows →
`Could not resolve "/e/..."` → **0/20 fungsi** ter-bundle (termasuk yang tidak
diubah). Script ini LANGSUNG dipakai deploy: `netlify.toml`
`[build] command = "bash scripts/build-netlify-functions.sh"`.
Fix: `cd "$ROOT"` + semua path RELATIF (portabel Linux & Git Bash); stderr
esbuild DITANGKAP & dicetak saat gagal (dulu `2>/dev/null` → "❌ Failed" tanpa
sebab, itu sebabnya bug ini lama tak terlihat). Hasil: **20/20 fungsi** OK.
Catatan: `scripts/prebuild-netlify.sh` (strip `.ts` via `sed -i` ke file sumber)
TIDAK direferensikan siapa pun = dead code & berbahaya bila dijalankan. Belum dihapus.

## 4. (Bonus) `vitest.config.ts` menjalankan suite `_lib` DUA KALI
`exclude` di-override tanpa `.netlify`. Karena `build-netlify-functions.sh`
menyalin `netlify/functions/_lib` (termasuk 18 `*.test.ts`) ke
`.netlify/functions/_lib`, vitest ikut menjalankannya → 35 → 53 file test,
angka hasil menyesatkan. Fix: tambah `.netlify` + `dist` ke `exclude`.

# Lanjutan 4 — FIX "admin & siswa logout tiap selesai benerin CV AI" + audit fix translate

## Akar masalah (bug logout) — BUKAN sesi kedaluwarsa, tapi false-positive
`bukaMasterEksternalAdmin()` (js/03_candidate.ts) membuka AI CV lewat
`generateAiFormBridge` → `bukaFormBridge` → `window.location.href`, yaitu
**tab yang SAMA** (bukan window baru), sehingga ai_form.html **mewarisi
localStorage ADMIN**.

Rantai bug:
1. Guard VIP `verifikasiAksesAiCv()` di `js/pages/ai_form.ts` hanya
   early-return saat `asj_admin_login==='sukses'`; jalur kedua

2. `api-client.ts` memilih token berdasarkan
   `CANDIDATE_ACTIONS`/`getAppData:'kandidat'`: karena `asj_admin_login==='sukses'`
   → yang terkirim **token ADMIN**, bukan token kandidat.
3. `handleGetAppData` (actions-public.ts): `valid = t && t.role===role &&
   ...` dengan `role='kandidat'` → token admin `role==='admin'` → **valid=false**
   → balas `sessionInvalid: true` padahal token admin masih SAH.
4. `api-client.ts` blok `sessionInvalid` → refresh gagal (role retry salah) →
   **menghapus SEMUA sesi** (`asj_admin_login/session`, `asj_kandidat_*`) +
   `window.location.reload()` → admin mendarat di layar login.

## Perbaikan
1. **Server (`netlify/functions/_lib/actions-public.ts` → handleGetAppData)** —
   tambah `isAdminView`: bila mode `kandidat` tapi token valid ber-role
   `admin` (dan `kind !== 'refresh'`), JANGAN anggap sesi mati. Tetap lanjut
   ambil data kandidat target dan **tidak menyertakan `sessionInvalid`**.
   - `w` (WA target) untuk mode kandidat: `t.wa` dulu; kalau token admin
     (tak punya wa) → fallback `payload[1]` (admin memang berwenang memilih).
   - Token refresh & token benar-benar rusak/kadaluwarsa TETAP `sessionInvalid`
     (isAdminView mensyaratkan `t` truthy).
   - Pola ini konsisten dengan `isOwnerOrAdmin()` dan `handleSubmitDataAsj`
     yang sudah menerima dua role.
2. **Frontend (`js/pages/ai_form.ts` → verifikasiAksesAiCv)** — guard tidak
   lagi memanggil `getAppData('kandidat')` kalau `asj_kandidat_session` tidak

   memicu request ber-token admin yang bisa menghapus sesi.
